# 1단계: SDK 기본 사항

> **시간:** 5분

## 한 문장으로 알아보는 SDK

GitHub Copilot SDK를 사용하면 애플리케이션에서 Copilot 대화를 시작하고, 응답을 스트리밍하며,
특정 애플리케이션 함수를 도구로 제공할 수 있습니다.

SDK는 직접 호스팅하는 모델이 아닙니다. 애플리케이션은 모델 요청과 도구 호출을 조율하는
**Copilot 런타임(Runtime)**에 연결됩니다.

| 용어 | 이 워크숍에서 하는 일 |
| --- | --- |
| 클라이언트(Client) | 런타임을 시작하고 연결하며 인증을 확인합니다. |
| 세션(Session) | 하나의 대화와 그 구성, 메시지 및 도구 결과를 보관합니다. |
| 프롬프트(Prompt) | 한 문장 작성과 같이 이번 턴에서 수행할 작업을 지정합니다. |
| 이벤트(Event) | 텍스트 조각, 도구 활동, 오류 또는 완료된 턴을 보고합니다. |
| 도구(Tool) | RSS 조회와 같이 모델이 요청할 수 있는, 이름이 지정된 애플리케이션 함수입니다. |

기본 루프는 다음과 같습니다.

```text
Your app -> client -> session -> prompt
                              <- response events
Your app <- permission request <- tool request
Your app -> tool result        -> next model response
```

하나의 클라이언트에서 여러 세션을 처리할 수 있습니다. 이 입문 과정에서는 프로그램을 실행할
때마다 클라이언트 하나와 세션 하나를 만들고 둘 다 닫습니다. 웹 서버, 에이전트 프레임워크 또는
데이터베이스는 필요하지 않습니다.

## 애플리케이션 열기

아래 진입점과 함께 **`LIVE_DEMO.md`**를 엽니다. 이 파일의 **Act One**이 워크숍에서
직접 수행할 순서입니다.

1. 클라이언트를 시작합니다.
2. 인증을 확인합니다.
3. 세션을 만듭니다.
4. hello world를 전송합니다.

스타터의 `Step 4` 주석은 이벤트 처리를 표시하며, 이벤트 처리는 가이드에서 제공하거나
설명합니다. 코드에서 전송은 `Step 5`로 표시되어 있습니다. 이 표시는 스캐폴드의 위치이며
가이드의 편집 네 단계 외에 추가로 수행할 실습이 아닙니다.

## 제어할 수 있는 항목

**애플리케이션**은 모델, 세션 ID, 공개할 도구 및 권한 정책을 선택합니다.
**모델**은 해당 설정 안에서 텍스트와 도구 호출을 제안합니다. 권한 처리기는 요청된 기능의
실행 허용 여부에 응답합니다.

스트리밍은 응답을 표시하는 방식을 바꿀 뿐 응답의 신뢰성을 높이지는 않습니다. 시스템 메시지는
동작을 안내하지만 접근 제어 메커니즘이나 사실 정확성의 증거는 아닙니다. 도구를 사용하면
애플리케이션에서 실제 원본 데이터를 제공할 수 있지만, 결과 텍스트는 여전히 검토해야 합니다.

첫 실행의 작업은 한 문장으로 된 hello world를 작성하는 것뿐입니다. 두 번째 실행에서는
애플리케이션이 미리 빌드된 읽기 전용 RSS 도구 두 개를 허용하고 사용 승인을 요청합니다.
이 트랙에서는 피드 파서를 작성하거나 MCP를 구성하지 않습니다.

## 이해도 확인

클라이언트가 시작되는 위치와 세션이 생성되는 위치를 짚어 봅니다.
차이점을 한 문장으로 설명합니다. 클라이언트는 런타임에 연결하고 세션은 대화를 나타냅니다.

[스트리밍 hello world](intro-02-hello-world.md)로 계속 진행합니다.
