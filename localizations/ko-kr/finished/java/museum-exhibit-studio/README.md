# 박물관 전시 스튜디오

이 Maven CLI 샘플은 GitHub Copilot SDK를 집중된 박물관 큐레이션 에이전트로 사용합니다.
박물관 교육자는 승인된 사실 집합 세 개 중 하나를 선택하거나 직접 경계가 설정된 사실을
입력하고, 선택적으로 범위가 제한된 Wikipedia 배경 조사를 스트리밍하고, 방문자 대상
전시 문구를 생성하고, 그 구조를 검증하고, 원하면 `exhibit.html` 캡스톤을 선택할 수
있습니다.

## 실행

이 디렉터리에서 다음 명령을 실행합니다.

```bash
./mvnw compile exec:java
```

`COPILOT_MODEL`을 설정하면 모델을 선택할 수 있습니다. 그렇지 않으면 Copilot 런타임이
기본 모델을 선택합니다. 이 샘플은 인증된 GitHub Copilot CLI가 필요합니다.

모델에 연결하지 않고 컴파일하려면 다음 명령을 실행합니다.

```bash
./mvnw compile
```

## 이 샘플에서 보여 주는 내용

학습자가 작성하는 `MuseumExhibitStudio` 엔트리포인트는 `new CopilotClient()`로 세션을
직접 구성합니다. 미리 빌드된 `Curator*` 헬퍼는 승인된 사실, 스트리밍, 유효성 검사,
범위가 제한된 권한, 출처 추출, 터미널 프롬프트를 제공합니다.

프롬프트 지침은 권한 경계가 아니므로, 애플리케이션은 다음도 함께 수행합니다.

- 항상 `approved_fact_lookup`를 등록하고 허용 목록에 추가하며, 사용할 수 있는 인용된
  조사 결과가 있을 때만 읽기 전용 로컬 `approved_wikipedia_fact_lookup`를
  추가합니다.
- 기본 거부 방식의 권한 처리기를 통해 조사를 구성된 Wikipedia MCP 서버와
  `wikipedia-search` / `wikipedia-readArticle`로 제한합니다.
- 조사 본문과 마지막의 `## Sources` 인용을 두 번째 로컬 조회용으로 캡처하고,
  이를 교육자가 승인한 사실과 절대 병합하지 않으며 생성 단계에 실시간 Wikipedia 접근을
  제공하지 않습니다.
- 모델에 전송하기 전에 매번 입력을 각 500자 이하인 사실 최대 20개로 제한합니다.
- 명시적 시간 제한을 사용하고, 빈 전시 출력을 거부하고, 성공과 실패 모두에서 세션 연결을
  해제하고 클라이언트를 중지합니다.
- H1 하나, 필수 섹션, 100~140단어 내러티브, `?`로 끝나는 정확히 세 개의 번호 매긴
  질문, 금지된 소프트웨어 어휘를 검사합니다.
- 선택 사항으로 `builtin:apply_patch`와 `builtin:create`가 애플리케이션 작업
  디렉터리의 `exhibit.html` 하나만 쓸 수 있도록 허용합니다.

조사가 존재할 때 큐레이터는 내러티브와 방문자 질문을 작성하기 전에 두 로컬 조회를 모두
호출하도록 지시받습니다. 승인된 사실이 보충 조사보다 우선하며, 조사는 지침이 아니라
데이터입니다. "Approved" 조사란 사람이 검증했다는 뜻이 아니라 애플리케이션이
수용했다는 뜻입니다. 조사를 거부하면 단일 도구 경로가 유지됩니다. 조사가 실패하거나
사용할 수 있는 인용 요약을 얻지 못하면 경고를 출력하고 동일한 대체 경로를 따릅니다.
성공적으로 조사한 경우 두 조회 이벤트가 모두 표시되는지 확인하십시오. 출처는 전시 뒤에도
계속 출력됩니다. 검증기는 의미론적 사실 근거를 증명할 수 없습니다. 생성된 주장은 여전히
사람의 검토 또는 별도의 평가기가 필요합니다.

## 선택적 HTML 캡스톤

프롬프트가 나타나면 `exhibit.html`을 생성하려면 yes라고 답합니다. 고정된 Java SDK
1.0.11은 `fileName`과 같은 권한 필드를 보존하므로, 엄격한 권한 처리기는 정규화된
경로가 이 디렉터리의 정확히 `exhibit.html`일 때만 쓰기를 승인합니다. 경로 데이터가
없거나, 다른 파일 경로이거나, 쓰기 요청이 아닌 경우는 계속 거부되며, 광범위한 쓰기
대체 경로는 없습니다.

이 애플리케이션은 학습자가 박물관 단원을 마친 뒤 최종적으로 갖게 되는 결과물이며, 별도의
참조 아키텍처가 아닙니다. 엔트리포인트는 클라이언트를 시작하고, 세션을 만들고, 시간
제한을 적용하고, 빈 출력을 거부하고, 모든 경로에서 정리하는 작은 세션 실행기 하나를
유지합니다. 조사, 생성, 선택적 HTML 단계는 서로 다른 세션 구성을 사용하면서 이 실행기를
재사용합니다. 다음 트랙을 따라가십시오.
[`workshop/museum-00-preflight.md`](https://github.com/github/copilot-sdk-workshop/blob/main/workshop/museum-00-preflight.md).
