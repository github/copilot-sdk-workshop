# 박물관 전시 스튜디오

이 완성된 Node.js/TypeScript 샘플은 세 개의 소스 파일로 구성됩니다.

- `src/curator.ts`에는 미리 빌드된 헬퍼 모듈이 들어 있습니다. 여기에는 승인된 사실과
  사실 선택 메뉴, 경계가 설정된 스트리밍, 결정론적 유효성 검사, 범위가 제한된 Wikipedia
  권한, 선택적 `exhibit.html` 쓰기 권한, 고정된 프롬프트 텍스트, 실패 메시지가 포함됩니다.
- `src/system-messages.ts`에는 미리 빌드된 큐레이터 및 조사 시스템 메시지가 들어 있습니다.
- `src/index.ts`에는 학습자가 작성하는 SDK 코드가 들어 있습니다. 여기에는 전시 및 페이지
  프롬프트의 지침, 세션 구성, 세션 실행기, 선택적 조사, 생성, 유효성 검사, 선택적 HTML
  캡스톤이 포함됩니다.

`src/index.ts`의 `>>> BEGIN` / `<<< END` 주석은 수업에서 채우는 이름이 지정된
영역입니다. 각 `BEGIN` 줄은 해당 영역을 삽입하거나 교체하는 단계를 나열합니다.

## 샘플 실행

```bash
cd finished/nodejs/museum-exhibit-studio
npm ci
npm start
```

모델에 연결하지 않고 타입 검사를 하려면 `npm run build`를 사용합니다.

## 안전성 구조

생성은 항상 경계가 설정된 승인된 사실을 반환하는 `approved_fact_lookup`를 등록하고 허용
목록에 추가합니다. 사용할 수 있는 인용된 조사 결과가 있으면 읽기 전용 로컬 도구
`approved_wikipedia_fact_lookup`도 등록하고 허용 목록에 추가하며, 큐레이터에게
내러티브와 방문자 질문을 작성하기 전에 두 도구를 모두 호출하라고 요청합니다. 두 번째
조회는 실시간 Wikipedia 접근이 아니라 조사 본문과 인용의 스냅샷을 반환합니다. 승인된
사실이 우선하며, 조사는 지침이나 사람이 검증한 사실이 아니라 보충 데이터입니다. 선택적
Wikipedia 조사는 별도 세션에서 실행되며, 범위가 제한된 `search` 및 `readArticle`
도구, 기본 거부 방식 권한 처리기, 인용된 `## Sources`, JSON 계약이나 추가 제안 승인
루프가 없는 구성을 사용합니다. 조사는 교육자가 승인한 사실과 절대 병합되지 않습니다.
조사를 거부하면 원래의 단일 도구 경로가 유지됩니다. 조사가 실패하거나 인용이 있는 요약을
사용할 수 없으면 경고를 출력하고 동일한 대체 경로를 따릅니다. 출처는 전시 뒤에도 계속
출력됩니다. 조사 실행이 성공하면 생성 전에 두 로컬 조회 이벤트가 모두 나타나는지
확인합니다.

생성 후에는 결정론적 검사가 구조, 내러티브 길이, 방문자 질문, 금지된 어휘를 보고합니다.
선택한 경우 HTML 단계는 `builtin:apply_patch`와 `builtin:create`만 노출합니다. 이
단계의 권한 처리기는 앱 디렉터리에서 정확히 `exhibit.html`에 쓰는 경우만 승인합니다.
구조 검사는 사실적 근거를 증명하지 않으므로, 게시 전에 조사된 주장을 검토해야 합니다.

이 애플리케이션은 학습자가 박물관 단원을 마친 뒤 최종적으로 갖게 되는 결과물이며, 별도의
참조 아키텍처가 아닙니다. 엔트리포인트는 클라이언트를 시작하고, 세션을 만들고, 시간
제한을 적용하고, 빈 출력을 거부하고, 모든 경로에서 정리하는 작은 세션 실행기 하나를
유지합니다. 조사, 생성, 선택적 HTML 단계는 서로 다른 세션 구성을 사용하면서 이 실행기를
재사용합니다. 다음 트랙을 따라가십시오.
[`workshop/museum-00-preflight.md`](https://github.com/github/copilot-sdk-workshop/blob/main/workshop/museum-00-preflight.md).
