# 박물관 전시 스튜디오

이 Go 샘플은 GitHub Copilot SDK를 집중된 박물관 큐레이션 하니스로 사용합니다. 애플리케이션은
세 개의 소스 파일로 구성됩니다.

- `curator.go`에는 승인된 사실 집합과 사실 선택 메뉴, 사실 경계, 응답 스트리밍, 구조 유효성 검사,
  Wikipedia 권한, 출처 추출, 선택적 `exhibit.html` 쓰기 권한, 고정된 프롬프트 텍스트, 실패 메시지를
  제공하는 미리 빌드된 헬퍼 API가 들어 있습니다.
- `system_messages.go`에는 미리 빌드된 큐레이터 및 조사 시스템 메시지가 들어 있습니다.
- `main.go`에는 학습자가 작성하는 SDK 코드가 들어 있습니다. 여기에는 전시 및 페이지 프롬프트의
  지침, 세션 구성, 세션 실행기, 정리가 포함됩니다.

`main.go`의 `>>> BEGIN` / `<<< END` 주석은 수업에서 채우는 이름이 지정된 영역입니다. 각
`BEGIN` 줄은 해당 영역을 삽입하거나 교체하는 단계를 나열합니다.

## 샘플 실행

이 디렉터리에서 다음 명령을 실행합니다.

```bash
go run .
```

`COPILOT_MODEL`을 설정하면 생성 모델을 선택할 수 있습니다. 그렇지 않으면 런타임이 기본
모델을 선택합니다. 인증된 GitHub Copilot CLI가 필요합니다.

모델이나 Wikipedia에 연결하지 않고 빌드하려면 다음 명령을 실행합니다.

```bash
go build -mod=readonly ./...
```

## 이 샘플에서 배울 내용

생성은 replace 방식 시스템 메시지를 사용하며, 경계가 설정된 승인된 사실을 반환하는
`approved_fact_lookup`를 항상 등록하고 허용 목록에 추가합니다. 사용할 수 있는 인용된
조사 결과가 있으면 읽기 전용 로컬 `approved_wikipedia_fact_lookup`도 등록하고 허용
목록에 추가하며, 내러티브와 방문자 질문을 작성하기 전에 두 호출을 모두 수행하도록
요청합니다. 이 조회는 실시간 Wikipedia 접근이 아니라 요약 본문과 인용의 스냅샷을
반환합니다. 승인된 사실이 우선합니다. 생성은 이벤트 스트리밍과 120초 시간 제한도
사용합니다. 선택적 Wikipedia 조사는 90초짜리 별도 세션에서 실행되며, 범위가 제한된 검색
도구와 기사 읽기 도구만 노출하고 기본 거부 방식의 권한 처리기를 사용합니다. 조사는 검색,
읽기, 참조한 문서를 마지막의 `## Sources` 섹션에 인용합니다. 애플리케이션은 해당 본문과
출처를 로컬 조회용으로 유지하지만 교육자가 승인한 사실과 병합하지는 않습니다. 여기서
"승인된"은 사람이 검증했다는 뜻이 아니라 애플리케이션이 보조 용도로 수용했다는
뜻이므로, 결과를 지침이 아니라 데이터로 취급해야 합니다. 조사를 거부하면 단일 도구 경로가
유지됩니다. 조사가 실패하거나 인용이 있는 요약을 사용할 수 없으면 경고를 출력하고 동일한
대체 경로를 따릅니다. 엄격한 조사 JSON 계약이나 승인 루프는 없습니다.

생성 후에는 결정론적 유효성 검사가 H1 하나, 필수 섹션, 100~140단어 내러티브, `?`로
끝나는 정확히 세 개의 번호 매긴 방문자 질문, 금지된 소프트웨어 용어를 검사합니다.
참조한 Wikipedia 출처는 생성된 본문 밖에서 전시 뒤에 출력됩니다. 조사가 성공적으로
실행되면 생성 전에 두 로컬 조회 이벤트가 모두 표시되는지 확인합니다. 구조 검사는 사실적
근거를 증명하지 않으므로, 게시 전에 조사된 주장을 검토해야 합니다.

선택 사항으로 애플리케이션은 `builtin:apply_patch` 또는 `builtin:create`를 사용해
`exhibit.html` 생성을 Copilot에 요청할 수 있습니다. 해당 세션은 애플리케이션 작업
디렉터리에서 정규화된 `exhibit.html` 하나에 대한 쓰기만 허용하고, 다른 모든 파일, 셸,
MCP 권한 요청은 거부합니다. HTML 프롬프트는 포함된 CSS와 JavaScript가 있는 독립 실행형
시맨틱 문서, 사람 검토 경고, 접근 가능한 질문 필터를 요구합니다.

이 애플리케이션은 학습자가 박물관 단원을 마친 뒤 최종적으로 갖게 되는 결과물이며, 별도의
참조 아키텍처가 아닙니다. 엔트리포인트는 클라이언트를 시작하고, 세션을 만들고, 시간
제한을 적용하고, 빈 출력을 거부하고, 모든 경로에서 정리하는 작은 세션 실행기 하나를
유지합니다. 조사, 생성, 선택적 HTML 단계는 서로 다른 세션 구성을 사용하면서 이 실행기를
재사용합니다. 다음 트랙을 따라가십시오.
[`workshop/museum-00-preflight.md`](https://github.com/github/copilot-sdk-workshop/blob/main/workshop/museum-00-preflight.md).
