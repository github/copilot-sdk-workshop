# Museum Exhibit Studio

この Maven CLI サンプルでは、GitHub Copilot SDK を焦点を絞った博物館キュレーションエージェントとして使用します。博物館の教育担当者は、3 つの承認済み事実セットのいずれかを選択するか、境界が適用された独自の事実を入力し、任意でスコープ指定済み Wikipedia 背景調査をストリーミングし、来館者向けの展示コピーを生成し、その構造を検証し、`exhibit.html` の総仕上げにオプトインできます。

## 実行

このディレクトリから:

```bash
./mvnw compile exec:java
```

モデルを選択するには、`COPILOT_MODEL` を設定します。設定しない場合、Copilot ランタイムは既定を選択します。このサンプルには、認証済みの GitHub Copilot CLI が必要です。

モデルに接続せずにコンパイルするには:

```bash
./mvnw compile
```

## 実演する内容

学習者が作成する `MuseumExhibitStudio` エントリポイントは、`new CopilotClient()` で直接セッションを構築します。あらかじめ用意された `Curator*` ヘルパーは、承認済みの事実と事実選択メニュー、ストリーミング、検証、スコープ指定済み権限、ソース抽出、固定のプロンプトテキスト、失敗メッセージ、そして (`CuratorSystemMessages.java` 内の) キュレーターと調査のシステムメッセージを提供します。エントリポイント内の `>>> BEGIN` / `<<< END` コメントは、レッスンが埋める名前付きリージョンです。各 `BEGIN` 行には、そのリージョンを挿入または置換するステップが列挙されています。

プロンプトによる指示は認可境界ではないため、アプリケーションはさらに次のことも行います:

- `approved_fact_lookup` を常に登録して許可リストに追加し、使用可能な引用付き調査が存在する場合にのみ、読み取り専用のローカル `approved_wikipedia_fact_lookup` を追加します。
- 既定で拒否する権限ハンドラーを通じて、調査を構成済みの Wikipedia MCP サーバーと `wikipedia-search` / `wikipedia-readArticle` に制限します。
- 2 つ目のローカル検索のために、調査本文と末尾の `## Sources` 引用をキャプチャし、教育担当者が承認した事実にマージしたり、生成にライブの Wikipedia アクセスを与えたりすることはありません。
- すべてのモデル送信の前に、入力を最大 20 件の事実に制限し、各事実を最大 500 文字にします。
- 明示的なタイムアウトを使用し、空白の展示出力を拒否し、成功時と失敗時にセッションを切断し、クライアントを停止します。
- 1 つの H1、必須セクション、100 ～ 140 語の展示解説文、`?` で終わる正確に 3 つの番号付き質問、禁止されたソフトウェア語彙をチェックします。
- 任意で、`builtin:apply_patch` と `builtin:create` がアプリケーションの作業ディレクトリ内の `exhibit.html` だけを書き込むことを許可します。

調査が存在する場合、キュレーターは展示解説文と来館者の質問を書く前に、両方のローカル検索を呼び出すよう指示されます。承認済みの事実は、指示ではなくデータである補足調査よりも優先されます。"Approved" 調査は、アプリケーションが受け入れたという意味であり、人間が検証したという意味ではありません。調査を辞退した場合は、単一ツールのパスが維持されます。調査に失敗した場合、または使用できない引用付き要約の場合は、警告が出力され、同じフォールバックが使用されます。調査が正常に実行されたら、両方の検索イベントを確認します。ソースは展示の後にも出力されます。バリデーターは意味的に事実に基づいていることを証明できません。生成された主張には、人間によるレビューまたは別の評価ツールが引き続き必要です。

## 任意の HTML 総仕上げ

プロンプトが表示されたら、yes と答えて `exhibit.html` を生成します。固定された Java SDK 1.0.11 は `fileName` などの権限フィールドを保持するため、厳密な権限ハンドラーは、正規化されたパスがこのディレクトリ内の `exhibit.html` と完全に一致する場合にのみ書き込みを承認します。パスデータの欠落、他のファイルパス、書き込み以外のリクエストは引き続き拒否され、広範な書き込みフォールバックはありません。

これは、Museum レッスンの後に学習者が最終的に作るアプリケーションであり、別個の参照アーキテクチャではありません。エントリポイントは、クライアントを開始し、セッションを作成し、タイムアウトを適用し、空白の出力を拒否し、すべての実行経路でクリーンアップする小さなセッションランナーを 1 つ保持します。調査、生成、任意の HTML ステップでは、異なるセッション構成でこれを再利用します。[`workshop/museum-00-preflight.md`](https://github.com/github/copilot-sdk-workshop/blob/main/workshop/museum-00-preflight.md) からトラックに従って進めます。
