# Museum Exhibit Studio

この完成した .NET サンプルでは、GitHub Copilot SDK を使用して、承認済みの事実から小さな博物館展示を生成します。あらかじめ用意された `Helpers/Curator*.cs` ファイルは、事実セットと事実選択メニュー、境界チェック、ストリーミング、決定論的な検証、スコープ指定済み Wikipedia 権限、スコープ指定済み `exhibit.html` 書き込み権限、固定のプロンプトテキスト、失敗メッセージを提供し、`Helpers/CuratorSystemMessages.cs` はキュレーターと調査のシステムメッセージを保持します。`Program.cs` は学習者が作成したままです。展示とページのプロンプト内の指示を書き、3 つのセッション構成を作成し、それぞれを 1 つのセッションランナーで実行します。

`Program.cs` の `>>> BEGIN` / `<<< END` コメントは、レッスンが埋める名前付きリージョンです。各 `BEGIN` 行には、そのリージョンを挿入または置換するステップが列挙されているため、ファイルを見ると各部分をどのステップが生成したかがわかります。

## サンプルを実行する

リポジトリルートから:

```bash
dotnet run --project finished/dotnet/museum-exhibit-studio
```

モデルを選択するには、実行前に `COPILOT_MODEL` を設定します。設定しない場合、Copilot ランタイムは既定を選択します。このサンプルには、認証済みの GitHub Copilot CLI が必要です。

モデルに接続せずにビルドするには:

```bash
dotnet build finished/dotnet/museum-exhibit-studio
```

## このサンプルで学べること

生成セッションは、アプリケーションが所有するツール `approved_fact_lookup` を常に登録して許可リストに追加します。使用可能な引用付き調査が存在する場合は、`approved_wikipedia_fact_lookup` も登録して許可リストに追加し、プロンプトは展示解説文と来館者の質問を書く前に両方の呼び出しを要求します。置換モードのシステムメッセージは、承認済みの事実を優先し、ツール結果を指示ではなくデータとして扱います。`CuratorFacts.CreateApprovedFactLookup` はモデルがそれらの事実を見る前に境界を適用し、`CuratorFacts.BoundFacts` は生成または調査の送信前に毎回事実をトリミングして検証し、`CuratorStreamer.StreamExhibitAsync` は明示的なタイムアウトでモデル出力をストリーミングします。

任意の Wikipedia 調査は、意図的に軽量にしています。別のセッションが、`CuratorSafety.WikipediaPermissionHandler` を通じて、スコープ指定済みの `search` と `readArticle` MCP ツールだけを公開します。モデルは散文のメモと末尾の `## Sources` リストを書きます。アプリは引用されたソースのタイトルと URL を抽出し、要約本文を保持します。`CuratorFacts.CreateApprovedWikipediaFactLookup` は、ネットワークアクセスなしで、その本文と引用のキャプチャ済みスナップショットを返します。調査は補足情報であり、教育担当者が承認した事実にマージされることはありません。"approved" は、アプリケーションが受け入れたという意味であり、人間が検証したという意味ではありません。調査を辞退した場合は、単一ツールのパスが維持されます。調査に失敗した場合、または引用のない要約の場合は、警告が出力され、同じフォールバックが使用されます。ソースは展示の後にも出力されます。

生成後、決定論的な検証によって、タイトル、`## Narrative`、100 ～ 140 語の展示解説文の長さ、`## Visitor questions`、正確に 3 つの番号付き質問、疑問符、禁止語彙がチェックされます。これらの構造チェックは事実に基づいていることを証明しないため、人間によるレビューが引き続き必要です。

任意の総仕上げでは、`builtin:apply_patch` または `builtin:create` を使用して `exhibit.html` を作成します。`CuratorSafety.ExhibitWritePermission` は、アプリケーションの作業ディレクトリ内のその 1 つのファイルだけを許可し、それ以外の書き込み、シェル、MCP リクエストはすべて拒否します。

## 手動チェック

1. サンプルを実行し、組み込みの事実セットの 1 つを受け入れます。
2. 調査にオプトインし、展示の前に両方のローカル検索イベントが表示され、ソースがその後に出力されることを確認します。調査を辞退し、`approved_fact_lookup` だけが呼び出されることを確認します。
3. 展示に 1 つのタイトル、100 ～ 140 語の展示解説文、3 つの質問が含まれていることを確認します。
4. 検証サマリーと人間によるレビューの注意事項が表示されることを確認します。
5. 任意で `exhibit.html` を生成し、スタンドアロンのインタラクティブページをブラウザーで確認します。

これは、Museum レッスンの後に学習者が最終的に作るアプリケーションであり、別個の参照アーキテクチャではありません。エントリポイントは、クライアントを開始し、セッションを作成し、タイムアウトを適用し、空白の出力を拒否し、すべての実行経路でクリーンアップする小さなセッションランナーを 1 つ保持します。調査、生成、任意の HTML ステップでは、異なるセッション構成でこれを再利用します。[`workshop/museum-00-preflight.md`](https://github.com/github/copilot-sdk-workshop/blob/main/workshop/museum-00-preflight.md) からトラックに従って進めます。
