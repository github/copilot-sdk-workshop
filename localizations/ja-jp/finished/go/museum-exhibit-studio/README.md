# Museum Exhibit Studio

この Go サンプルでは、GitHub Copilot SDK を焦点を絞った博物館キュレーションハーネスとして使用します。このアプリには 3 つのソースファイルがあります:

- `curator.go` には、あらかじめ用意されたヘルパー API が含まれています。承認済みの事実セットと事実選択メニュー、事実境界、応答ストリーミング、構造検証、Wikipedia 権限、ソース抽出、任意の `exhibit.html` 書き込み権限、固定のプロンプトテキスト、失敗メッセージです。
- `system_messages.go` には、あらかじめ用意されたキュレーターと調査のシステムメッセージが含まれています。
- `main.go` には、学習者が作成する SDK コードが含まれています。展示とページのプロンプト内の指示、セッション構成、セッションランナー、クリーンアップです。

`main.go` の `>>> BEGIN` / `<<< END` コメントは、レッスンが埋める名前付きリージョンです。各 `BEGIN` 行には、そのリージョンを挿入または置換するステップが列挙されています。

## サンプルを実行する

このディレクトリから:

```bash
go run .
```

生成モデルを選択するには、`COPILOT_MODEL` を設定します。設定しない場合、ランタイムは既定を選択します。認証済みの GitHub Copilot CLI が必要です。

モデルや Wikipedia に接続せずにビルドするには:

```bash
go build -mod=readonly ./...
```

## このサンプルで学べること

生成では、置換用システムメッセージを使用し、境界が適用された承認済みの事実を返す `approved_fact_lookup` を常に登録して許可リストに追加します。使用可能な引用付き調査がある場合は、読み取り専用のローカル `approved_wikipedia_fact_lookup` も登録して許可リストに追加し、展示解説文と来館者の質問を書く前に両方の呼び出しを要求します。その検索は、ライブの Wikipedia アクセスではなく、要約本文と引用のスナップショットを返します。承認済みの事実が優先されます。生成ではイベントストリーミングと 120 秒のタイムアウトも使用します。任意の Wikipedia 調査は、スコープ指定済みの検索ツールと記事読み取りツールに加え、既定で拒否する権限ハンドラーだけを備えた別の 90 秒セッションで実行されます。調査は、参照した記事を検索、読み取り、末尾の `## Sources` セクションで引用します。アプリは、教育担当者が承認した事実にマージすることなく、ローカル検索用に本文とソースを保持します。"Approved" は、補足利用のためにアプリケーションが受け入れたという意味であり、人間が検証したという意味ではありません。結果は指示ではなくデータとして扱います。調査を辞退した場合は、単一ツールのパスが維持されます。調査に失敗した場合、または使用できない引用付き要約の場合は、警告が出力され、同じフォールバックが使用されます。厳密な調査 JSON コントラクトや承認ループはありません。

生成後、決定論的な検証によって、1 つの H1、必須セクション、100 ～ 140 語の展示解説文、`?` で終わる正確に 3 つの番号付き来館者の質問、禁止されたソフトウェア用語がチェックされます。参照した Wikipedia ソースは、生成されたコピーの外側で、展示の後に出力されます。調査が正常に実行された場合は、生成前に両方のローカル検索イベントが表示されることを確認します。構造チェックは事実に基づいていることを証明しないため、公開前に調査済みの主張を確認してください。

任意で、アプリは Copilot に `builtin:apply_patch` または `builtin:create` を使用して `exhibit.html` を作成するよう依頼できます。そのセッションは、アプリケーションの作業ディレクトリ内の `exhibit.html` への正規化済みの単一書き込みだけを許可し、それ以外のすべてのファイル、シェル、MCP 権限リクエストを拒否します。HTML プロンプトでは、CSS と JavaScript を埋め込んだスタンドアロンのセマンティックドキュメント、人間によるレビューの注意事項、アクセシブルな質問フィルターが必要です。

これは、Museum レッスンの後に学習者が最終的に作るアプリケーションであり、別個の参照アーキテクチャではありません。エントリポイントは、クライアントを開始し、セッションを作成し、タイムアウトを適用し、空白の出力を拒否し、すべての実行経路でクリーンアップする小さなセッションランナーを 1 つ保持します。調査、生成、任意の HTML ステップでは、異なるセッション構成でこれを再利用します。[`workshop/museum-00-preflight.md`](https://github.com/github/copilot-sdk-workshop/blob/main/workshop/museum-00-preflight.md) からトラックに従って進めます。
