# Museum Exhibit Studio

この Rust サンプルでは、GitHub Copilot SDK を、ソフトウェアエンジニアリング以外に焦点を絞ったエージェントハーネスとして使用します。あらかじめ用意されたヘルパーは `src/lib.rs` にあります: 承認済みの事実セットと事実選択メニュー、ストリーミング、検証、スコープ指定された権限、固定プロンプトテキスト、失敗メッセージです。キュレーターと調査のシステムメッセージは `src/system_messages.rs` にあらかじめ用意されています。学習者が作成する SDK コードは `src/main.rs` にあります: 展示プロンプトとページプロンプト内の指示、セッション構成、セッションランナーです。

`src/main.rs` の `>>> BEGIN` / `<<< END` コメントは、レッスンで埋める名前付きリージョンです。各 `BEGIN` 行には、そのリージョンを挿入または置換するステップが列挙されています。

## サンプルを実行する

```bash
cargo run --manifest-path finished/rust/museum-exhibit-studio/Cargo.toml --locked
```

`COPILOT_MODEL` を設定して生成モデルを選択します。このサンプルには認証済みの GitHub Copilot CLI が必要です。

モデルに問い合わせずにチェックします:

```bash
cargo check --locked --manifest-path finished/rust/museum-exhibit-studio/Cargo.toml
```

## このサンプルで学べること

生成セッションでは、置き換え用のキュレーターシステムメッセージを使用し、承認済みの事実を検証し、120 秒のタイムアウトでストリーミングし、常に `approved_fact_lookup` を登録して許可リストに追加し、空の出力を拒否し、決定的な構造検証を出力します。使用可能で引用付きの調査がある場合は、読み取り専用のローカル `approved_wikipedia_fact_lookup` も登録して許可リストに追加し、ナラティブと来館者の質問を書く前に両方の呼び出しを要求します。

省略可能な Wikipedia 調査は分離されています。スコープ指定された `search` と `readArticle` MCP ツールのみを公開し、既定で拒否する権限ハンドラーを使用し、サマリーと引用付きソースを生成します。新しいローカルルックアップは、その本文と引用のスナップショットを返します。ライブの Wikipedia アクセスは行わず、調査を教育者承認済みの事実にマージすることもありません。承認済みの事実が優先されます。"approved" 調査は、アプリケーションが受け入れた補足データであり、人間が検証した事実や指示ではありません。調査を辞退した場合は単一ツールパスを維持します。調査に失敗した場合、または使用できない引用付きサマリーになった場合は、警告を出力して同じフォールバックに進みます。Sources は展示の後に出力されます。調査が成功した場合は、生成前に両方のローカルルックアップイベントが表示されるはずです。構造チェックは事実に基づいていることを証明しないため、公開前に調査された主張をレビューしてください。

省略可能な HTML 生成では、アプリケーションの作業ディレクトリ内の `exhibit.html` だけに書き込める単一ファイル権限ハンドラーとともに、`builtin:apply_patch` または `builtin:create` を使用します。

これは、Museum レッスンの後に学習者が最終的に作るアプリケーションであり、別個の参照アーキテクチャではありません。エントリポイントは、クライアントを開始し、セッションを作成し、タイムアウトを適用し、空白の出力を拒否し、すべての実行経路でクリーンアップする小さなセッションランナーを 1 つ保持します。調査、生成、任意の HTML ステップでは、異なるセッション構成でこれを再利用します。[`workshop/museum-00-preflight.md`](https://github.com/github/copilot-sdk-workshop/blob/main/workshop/museum-00-preflight.md) からトラックに従って進めます。
