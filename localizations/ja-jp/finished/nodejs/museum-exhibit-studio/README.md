# Museum Exhibit Studio

この完成した Node.js/TypeScript サンプルには、3 つのソースファイルがあります:

- `src/curator.ts` には、あらかじめ用意されたヘルパーモジュールが含まれています。承認済みの事実と事実選択メニュー、境界付きストリーミング、決定論的な検証、スコープ指定済み Wikipedia 権限、任意の `exhibit.html` 書き込み権限、固定のプロンプトテキスト、失敗メッセージです。
- `src/system-messages.ts` には、あらかじめ用意されたキュレーターと調査のシステムメッセージが含まれています。
- `src/index.ts` には、学習者が作成する SDK コードが含まれています。展示とページのプロンプト内の指示、セッション構成、セッションランナー、任意の調査、生成、検証、任意の HTML 総仕上げです。

`src/index.ts` の `>>> BEGIN` / `<<< END` コメントは、レッスンが埋める名前付きリージョンです。各 `BEGIN` 行には、そのリージョンを挿入または置換するステップが列挙されています。

## サンプルを実行する

```bash
cd finished/nodejs/museum-exhibit-studio
npm ci
npm start
```

モデルに接続せずに型チェックするには、`npm run build` を使用します。

## 安全性の構成

生成では常に、範囲を限定した承認済みの事実を返す `approved_fact_lookup` を登録し、許可リストに追加します。使用可能で引用付きの調査がある場合は、読み取り専用のローカルツール `approved_wikipedia_fact_lookup` も登録して許可リストに追加し、ナラティブと来館者の質問を書く前に両方を呼び出すようキュレーターに求めます。2 つ目のルックアップは、ライブの Wikipedia アクセスではなく、調査本文と引用のスナップショットを返します。承認済みの事実が優先されます。調査は補足データであり、指示や人間が検証した事実ではありません。省略可能な Wikipedia 調査は、スコープ指定された `search` と `readArticle` ツール、既定で拒否する権限ハンドラー、引用付きの `## Sources` を備え、JSON コントラクトや追加案の承認ループを持たない別のセッションで実行されます。調査が教育者承認済みの事実にマージされることはありません。調査を辞退した場合は元の単一ツールパスを維持します。調査に失敗した場合、または使用できない引用付きサマリーになった場合は、警告を出力して同じフォールバックに進みます。Sources は引き続き展示の後に出力されます。調査が成功した場合は、生成前に両方のローカルルックアップイベントが表示されることを確認してください。

生成後、決定的チェックによって、構造、ナラティブの長さ、来館者の質問、禁止語彙が報告されます。選択した場合、HTML ステップは `builtin:apply_patch` と `builtin:create` だけを公開します。その権限ハンドラーは、アプリディレクトリ内の正確に `exhibit.html` への書き込みを承認します。構造チェックは事実に基づいていることを証明しません。公開前に、調査された主張をレビューしてください。

これは、Museum レッスンの後に学習者が最終的に作るアプリケーションであり、別個の参照アーキテクチャではありません。エントリポイントは、クライアントを開始し、セッションを作成し、タイムアウトを適用し、空白の出力を拒否し、すべての実行経路でクリーンアップする小さなセッションランナーを 1 つ保持します。調査、生成、任意の HTML ステップでは、異なるセッション構成でこれを再利用します。[`workshop/museum-00-preflight.md`](https://github.com/github/copilot-sdk-workshop/blob/main/workshop/museum-00-preflight.md) からトラックに従って進めます。
