# ステップ 1: SDK の基本

> **所要時間:** 5 分

## SDK を一文で表すと

GitHub Copilot SDK を使うと、アプリケーションで Copilot 会話を開始し、応答をストリーミングし、特定のアプリケーション関数をツールとして公開できます。

SDK は自分でホストするモデルではありません。アプリケーションは**Copilot ランタイム**に接続し、ランタイムがモデルリクエストとツール呼び出しを調整します。

| 用語 | このワークショップでの役割 |
| --- | --- |
| クライアント | ランタイムを起動して接続し、認証を確認します。 |
| セッション | 1 つの会話、その構成、メッセージ、ツール結果を保持します。 |
| プロンプト | 1 文を書くなど、このターンのタスクを割り当てます。 |
| イベント | テキスト断片、ツールアクティビティ、エラー、完了したターンを報告します。 |
| ツール | RSS 検索など、モデルが要求できる名前付きアプリケーション関数です。 |

基本的なループは次のとおりです:

```text
Your app -> client -> session -> prompt
                              <- response events
Your app <- permission request <- tool request
Your app -> tool result        -> next model response
```

1 つのクライアントで複数のセッションを扱えます。この入門では、プログラム実行ごとに 1 つのクライアントと 1 つのセッションを作成し、その後両方を閉じます。Web サーバー、エージェントフレームワーク、データベースは必要ありません。

## アプリケーションを開く

以下のエントリポイントの横で **`LIVE_DEMO.md`** を開きます。その **第 1 幕** が、このワークショップのハンズオン手順です:

1. クライアントを起動します。
2. 認証を確認します。
3. セッションを作成します。
4. Hello World を送信します。

## 制御できるもの

**アプリケーション**はモデル、セッションの識別情報、公開するツール、権限ポリシーを選択します。**モデル**はその設定内でテキストとツール呼び出しを提案します。権限ハンドラーは、要求された機能を実行してよいかどうかに回答します。

ストリーミングによって変わるのは応答の表示方法であり、その信頼性ではありません。システムメッセージは振る舞いを導きますが、アクセス制御の仕組みでも事実の正確性の証明でもありません。ツールにより、アプリケーションは実際のソースデータを提供できますが、結果のテキストはそれでもレビューします。

初回実行では、タスクは 1 文の Hello World だけです。2 回目の実行では、アプリケーションが読み取り専用のあらかじめ用意された RSS ツール 2 つを許可し、その使用の承認を求めます。このトラックでは、フィードパーサーを書いたり MCP を構成したりしません。
