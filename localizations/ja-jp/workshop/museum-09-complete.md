# やり遂げました！

GitHub Copilot SDK で Museum Exhibit Studio を構築しました。最初のキュレーターセッションからインタラクティブな展示ページまで作り上げました。エージェントをソフトウェアライフサイクルの枠を越えて活用し、明確な仕事、独自の語り口、アプリケーションが所有する境界を与えました。

## 組み合わせたもの

- カスタムシステムメッセージと教育担当者が承認した事実を備えた、ストリーミングするキュレーター。
- 構造検証とスコープ設定された Wikipedia 調査。捕捉した出典情報は承認済みの事実とは別に保たれます。
- `exhibit.html` に制限された書き込み権限を通じて作成されるインタラクティブな展示ページ。

来館者と共有する前に展示をレビューしてください。構造チェックは事実の正確性を証明するものではなく、調査された主張には引き続き人間によるレビューが必要です。

## 詳細情報

- [Copilot SDK cookbook](https://github.com/github/copilot-sdk/tree/main/cookbook): 次のエージェントのための実用的なレシピ集です。
- [Copilot SDK ドキュメント](https://github.com/github/copilot-sdk/tree/main/docs): システムメッセージ、セッション、アプリケーション所有のツールについて詳しく学べます。

- [Model Context Protocol](https://modelcontextprotocol.io/): Wikipedia 調査セッションの背後にある標準を理解します。

## 構築を続ける

教育担当者が承認した新しい題材を試すか、キュレーターパターンを別の対象読者に適用してみてください。信頼できるソース素材、補助的な調査、生成されたコピーは明確に分けておきます。

下の **ワークショップハブに戻る** を使って、選択したプログラミング言語で Accessibility Reviewer を試すか、前のステップに戻って展示ページを磨きます。
